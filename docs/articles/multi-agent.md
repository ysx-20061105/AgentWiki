## 为什么需要多 Agent？

单个 Agent 在处理复杂任务时往往力不从心。多 Agent 系统通过**分工协作**，让每个 Agent 专注于自己擅长的领域，从而提升整体效果。

核心优势：

- **专业化分工**：每个 Agent 拥有不同的工具和专业知识
- **并行处理**：多个 Agent 可以同时工作
- **鲁棒性**：单个 Agent 失败不影响整个系统
- **可扩展性**：可以灵活添加或替换 Agent

## 常见设计模式

### 1. 主从模式（Orchestrator-Worker）

一个主 Agent 负责任务分配和协调，多个工作 Agent 负责具体执行。

```
            ┌──────────────┐
            │  Orchestrator │
            │  (主控 Agent)  │
            └──────┬───────┘
         ┌─────────┼─────────┐
         ▼         ▼         ▼
    ┌────────┐ ┌────────┐ ┌────────┐
    │Research│ │ Writer │ │Reviewer│
    │ Agent  │ │ Agent  │ │ Agent  │
    └────────┘ └────────┘ └────────┘
```

**适用场景**：任务可以清晰分解为子任务的工作流。

```python
# 伪代码示例
class Orchestrator:
    def run(self, task):
        # 1. 规划
        plan = self.llm.plan(task)

        # 2. 分配子任务
        results = []
        for subtask in plan:
            worker = self.select_worker(subtask)
            result = worker.execute(subtask)
            results.append(result)

        # 3. 整合结果
        return self.synthesize(results)
```

### 2. 对等协作模式（Peer-to-Peer）

所有 Agent 地位平等，通过消息传递进行协作。

```
    ┌────────┐    消息    ┌────────┐
    │ Agent A │ ◄──────► │ Agent B │
    └────┬───┘           └───┬────┘
         │     消息          │
         └──────►┌────────┐◄─┘
                 │ Agent C │
                 └────────┘
```

**适用场景**：需要多轮讨论和协商的创意任务。

### 3. 竞争模式（Debate）

多个 Agent 对同一问题给出不同答案，通过辩论选出最佳方案。

```
    ┌────────┐
    │ Agent A │─── 观点 A ───┐
    └────────┘               │
    ┌────────┐               ▼
    │ Agent B │─── 观点 B ──►裁判 Agent ──► 最终答案
    └────────┘               ▲
    ┌────────┐               │
    │ Agent C │─── 观点 C ───┘
    └────────┘
```

**适用场景**：需要高质量决策的场景，如代码审查、方案评审。

### 4. 流水线模式（Pipeline）

Agent 按顺序处理，前一个的输出作为后一个的输入。

```
    ┌────────┐    ┌────────┐    ┌────────┐
    │ 分析师  │───►│ 开发者  │───►│ 测试员  │
    └────────┘    └────────┘    └────────┘
```

**适用场景**：有明确阶段划分的工作流。

## 实践建议

### 选择合适的模式

| 模式 | 复杂度 | 适用场景 | 典型应用 |
|------|--------|---------|---------|
| 主从 | 中 | 可分解的任务 | 研究报告、内容生成 |
| 对等 | 高 | 创意讨论 | 头脑风暴、方案设计 |
| 竞争 | 中 | 决策优化 | 代码审查、方案评估 |
| 流水线 | 低 | 阶段性任务 | 数据处理、内容生产 |

### 通信协议设计

Agent 之间的通信需要定义清晰的消息格式：

```json
{
  "from": "research_agent",
  "to": "writer_agent",
  "type": "task_result",
  "content": "调研结果...",
  "metadata": {
    "confidence": 0.85,
    "sources": ["url1", "url2"]
  }
}
```

> **经验法则**：从简单的主从模式开始，随着需求增长再演进到更复杂的架构。过度设计是多 Agent 系统最常见的错误。

## 框架推荐

- **LangGraph**：基于图的 Agent 编排，灵活强大
- **CrewAI**：专注于角色扮演的多 Agent 框架

## 总结

多 Agent 系统是 Agent 技术发展的重要方向。选择合适的协作模式，定义清晰的通信协议，从简单架构开始迭代，是构建成功多 Agent 系统的关键。
